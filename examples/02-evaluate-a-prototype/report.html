Shelf twin evaluation

Shelf (static HTML prototype) · /home/claude/twinzies/evals/evaluate-app-with-twins/files/app.html, source read plus headless Chrome render and measurements, 2026-11-20

Shelf is a very small prototype: one search box, a camera icon, a one-row table, a checkbox and two buttons. Its three actions are not wired, the scan icon and 'Purge all' are not keyboard operable, and the data model has none of the fields the six collector twins rely on (edition, region, location, rip status, condition, price). The visual hierarchy is inverted: the destructive action is loudest and the primary action looks disabled.

2 blocker · 12 major · 5 minor · 0 polish

Not run: screen reader testing, real-device mobile and touch testing, reflow at 320 CSS px (headless Chrome enforces a 500px minimum window width), 200% browser zoom visual check, manual keyboard walkthrough (tab order read from the DOM, not driven by keystrokes), reduced-motion, dark mode and print checks, any interaction flow (handlers are undefined), real-user validation

Findings

F1 Every action handler is undefined: scan, Commit and Purge all do nothing

blocker observed

Functionality · Camera icon, Commit button, Purge all

scan(), commit() and del() are referenced by onclick but are not defined anywhere in the file (typeof returns 'undefined' for all three in headless Chrome). Clicking each throws a ReferenceError and nothing visible happens. No other script exists.

Why it matters. No twin can finish any task: scanning, saving a batch, or clearing is impossible. Marcus's and Dale's core jobs (scan 50 discs, check a title in a store) start at the scan control.

Suggested change. If this is a deliberate prototype stub, wire each control to a visible placeholder result (a toast, a fake result row) so walkthroughs and real-user tests exercise the flow. Otherwise implement the three handlers.

Affects: Marcus, the Barcode-Blitz Cataloger, Priya, the Edition Completionist, Walt, the Low-Vision Legacy Collector, Dale, the Pressing-Obsessed Digger, Kenji, the Regional-Variant Game Hunter, Rosa, the Rip-and-Shelf Homelabber

F2 Scan control is a 20x17 emoji span: no keyboard access, no name, tiny target

blocker observed

UI & interaction · Camera icon next to Search · WCAG 1.1.1, 2.1.1, 4.1.2, 2.5.8

The scan trigger is a <span class='icon' onclick> containing a camera emoji. It has no tabindex, no role, no accessible name, and is not in the tab order (only the search input, checkbox and Commit are focusable). Rendered size is 20x17 px with no gap from the search box. The 16x16 CSS size is overridden by the inline emoji.

Why it matters. Keyboard and screen reader users cannot scan at all. Marcus, Dale and Kenji rely on scanning, often one-handed in a store; Dale's evidence reports black-screen scanners and awkward small-screen apps, so a 17 px target adds to that. Walt may not recognise an unlabelled icon and avoids camera-dependent flows.

Suggested change. Option A: a real <button type='button'> with a visible 'Scan' label and an aria-label, min 44x44 on touch. Option B: icon plus text button placed first in the row, with typed UPC entry beside it. Keep it consistent with the app's button styling.

Affects: Marcus, the Barcode-Blitz Cataloger, Dale, the Pressing-Obsessed Digger, Kenji, the Regional-Variant Game Hunter, Walt, the Low-Vision Legacy Collector

F3 'Purge all' is an unguarded destructive action styled as plain red text

major observed

UI & interaction · Under the Commit button · WCAG 2.1.1, 4.1.2, 3.3.4, 1.4.3

'Purge all' is a <div onclick>, not a button. It sits directly under Commit with no gap, has no confirmation, undo or scope (purge what: the queue, the collection?), is not keyboard reachable, and has no pointer cursor. Red (#ff0000) on white is 4.0:1.

Why it matters. For Walt, Marcus (hundreds to thousands of discs) and Rosa (thousands ripped over years) an accidental purge means losing years of cataloguing; Marcus also distrusts anything he cannot export. A mis-tap beside the primary button is likely on a phone.

Suggested change. Option A: rename to a specific verb such as 'Clear queue', make it a secondary text button, separate it from Commit, and confirm with a count ('Remove 1 item?'). Option B: no confirm but a 10-second Undo toast. Do not offer 'purge all' at collection level without export first. Use a red of at least 4.5:1 (for example #b3261e is about 6.5:1).

Affects: Marcus, the Barcode-Blitz Cataloger, Priya, the Edition Completionist, Walt, the Low-Vision Legacy Collector, Dale, the Pressing-Obsessed Digger, Kenji, the Regional-Variant Game Hunter, Rosa, the Rip-and-Shelf Homelabber

F4 Emphasis is inverted: the destructive action is loudest, the primary action looks disabled

major observed

Hierarchy & IA · Bottom of the page · WCAG 1.4.11, 1.3.1

Commit is a grey (#ddd) 13px button with no border, 1.36:1 against the white page. Purge all is saturated red 16px text. The h1 'Shelf' is 14px, smaller than the 16px body and table text, so the page title is the quietest thing on screen. The eye lands on the red text first.

Why it matters. Users decide what is safe from visual weight. Walt is easily lost on dense screens; Marcus scans quickly and will hit what stands out.

Suggested change. Make Commit (or the renamed primary) the one filled, high-contrast button; render Purge/Clear as a quiet secondary; set the h1 above body size (about 24px). Offer two or three directions for the page structure to the design team: single-column queue list, or table plus sticky action bar.

Affects: Marcus, the Barcode-Blitz Cataloger, Priya, the Edition Completionist, Walt, the Low-Vision Legacy Collector, Dale, the Pressing-Obsessed Digger, Kenji, the Regional-Variant Game Hunter, Rosa, the Rip-and-Shelf Homelabber

F5 The only instruction line is #bbb at 11px (1.92:1 contrast)

major observed

Visual design · Hint text 'Ingest queue: reconcile metadata before commit' · WCAG 1.4.3

Colour #bbbbbb on #ffffff computes to 1.92:1 at 11px. It is the only explanatory text on the page. Body text (#222 on white) is 15.9:1, so this is an isolated failure.

Why it matters. Walt's documented pain is text he cannot read or enlarge; he will miss the only guidance. Everyone else will also skip it, so the screen loses its only orientation.

Suggested change. Raise to at least #595959 (about 7:1) and at least 14px, or fold the guidance into a heading and plain sentence. Do not rely on grey for text that tells people what to do.

F6 Internal jargon: 'Ingest queue', 'reconcile metadata', 'Commit', 'Fmt', 'SKU', 'BD'

Copy reads like a developer's data pipeline. 'Fmt' is an abbreviation of a word that fits on screen; 'SKU' shows 0883929 where collectors say UPC or barcode; 'Commit' does not say what is being saved; 'BD' is not defined; 'Purge all' is unclear in scope.

F19 Inconsistent type scale and an unstructured table

minor observed

Font sizes in use: 11px (hint), 13.3px (input and button), 14px (h1), 16px (table, label). The table has no borders, row separators, zebra or column widths, so the three columns sit tightly together (see Title/Fmt/SKU). A single row hides how it will look at hundreds of rows.

Tensions between twins

  • Rich release-level fields (Priya, Dale, Kenji, Rosa) versus Walt's need for a plain, large-text list that does not overwhelm him: use a simple default row with an expandable detail section.
  • Camera/scan-first entry (Marcus, Dale, Kenji) versus Walt, who may have no camera or scanner and relies on a family member typing: typed barcode and paste-a-list entry need to be equal citizens.
  • Vocabulary clash: Priya says 'edition' and 'release', Dale says 'pressing' (and may read 'edition' as ambiguous), Kenji says 'variant' and 'platform', Rosa reads 'collection' as a Plex grouping: no single label suits all, so pick one and add synonyms in help text.
  • Value and price tracking: Marcus wants price paid and Walt wants approximate value, but Kenji's evidence describes value tracking as anxiety-inducing for some: make price and value optional, off by default for display.
  • A single 'sealed' flag is enough for Marcus and Walt but too coarse for Kenji's loose/boxed/complete/sealed ladder.
  • Technical wording ('ingest', 'metadata', 'rip') is natural for Rosa but excludes Walt: default plain, allow technical labels on detail views.

What works

  • Body text is #222 on white (15.9:1) and uses real text, so it scales with browser zoom without fixed widths.
  • Native input, checkbox and button keep the browser's default focus ring (the CSS does not remove outlines), and they are in the tab order.
  • The checkbox is wrapped in a <label>, so clicking its words toggles it, and the data is in a real <table> with <th> header cells.
  • The 'Alien / BD / barcode' row shows the right idea: title, format and barcode in one scannable line.
  • A single h1 exists, and the layout is a single column with no horizontal scroll at the 780px width tested.
